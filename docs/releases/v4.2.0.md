# Release v4.2.0

[![GitHub Downloads](https://img.shields.io/github/downloads/alexdelprete/ha-abb-powerone-pvi-sunspec/v4.2.0/total?style=for-the-badge)](https://github.com/alexdelprete/ha-abb-powerone-pvi-sunspec/releases/tag/v4.2.0)

**Release Date:** TBD

**Type:** Minor release - Moves Modbus onto Home Assistant's shared Modbus connection, fixes a device registry
deprecation that would break setup in HA 2027.8, and adds a full test suite.

> **Requires Home Assistant 2026.9.0 or newer.** HACS does not offer this update to older versions; stay on
> v4.1.8 until you upgrade Home Assistant.

## What's Changed

### Added

- **Shared Modbus connection** - The integration now reads the inverter through Home Assistant's own Modbus
  connection layer ([modbus-connection](https://home-assistant-libs.github.io/modbus-connection/), bundled with
  HA) instead of opening a private pymodbus client. It no longer installs pymodbus, and it can share the
  inverter or datalogger with any other integration reading it over the same link
- **Clear error on conflicting link settings** - If another integration already uses the inverter with
  different Modbus link settings, setup stops with an explanatory error instead of fighting over the connection

### Changed

- **Minimum Home Assistant version is now 2026.9.0** (was 2025.10.0 in v4.1.8), the first release with the
  shared Modbus connection API
- **Entities, unique IDs and configuration are unchanged** - Existing installations keep their history,
  dashboards and automations
- Removed the vendored pymodbus payload and constants modules
- Repository onboarded to the shared integration template (CI workflows, pre-commit, devcontainer)

### Fixed

- **Device registry deprecation** - Stopped passing `via_device` to the device registry; Home Assistant
  deprecated it and setup would fail from HA 2027.8
- **Device deletion guard** - Deleting the inverter device on its own is now refused as intended ("remove the
  integration instead"); the check never matched before
- **Unknown inverter type** - An inverter type outside the known table no longer fails every poll with a
  `KeyError`; it is reported as "Unknown"
- **Empty options register** - An inverter reporting an empty options register no longer fails the first read
- **Total energy scale factor** - Read as signed, as SunSpec defines it
- **Options register** - A malformed hex model code no longer fails the first read
- **Typo** - Vendor operating state 32 reads "Fan Stuck" (was "Fan Staucked")
- **Operating State sensor** - Register 108 is the SunSpec operating state, but since 2021 it was looked up in
  ABB's Aurora inverter-state table, so a producing inverter (SunSpec `4` = MPPT) showed "Out OC". It now shows
  the SunSpec states: Off, Sleeping, Starting, MPPT, Throttled, Shutting Down, Fault, Standby.
  **Its values change: update any automation that tests this sensor.** ABB's own inverter state is unchanged in
  the **Vendor Operating State** sensor

### Tests

- New test suite running the real API, coordinator, config flow and sensor platform against an in-memory
  Modbus unit, covering single- and three-phase inverters, one or two MPPTs, alternate Model 160 offsets,
  base address 40000, and connection failures
